MIRA tests a formal hypothesis: can a radial, hierarchical, graph-based memory topology, using rings and sectors instead of flat vectors, improve how machines retrieve and reason? The system is built to prove it wrong as easily as right.

What MIRA is not. MIRA is an experimental architecture inspired by the organizational and visual principles of mandalas/yantras. It does not claim that historical mandalas were neural networks or that ancient traditions contained modern AI. Whether radial organization helps is an empirical question: negative results are reported, not hidden.

Does radial topology earn its place?

When model, context budget, dataset and hardware are held constant, does arranging memory in concentric rings around a core, measured by a formal radial distance, retrieve better evidence for multi-hop questions than flat vector search?

The formula under test

score = α·semantic + β·structural + γ·radial
+ δ·graph + ε·importance + ζ·confidence
+ η·recency + θ·path + ι·activation
+ κ·stability (BioMIRA layer only)

Ten components, one Greek letter each — the same mapping the code uses. Every coefficient is configurable and every component can be switched off, which makes the contribution testable rather than decorative.

The honest baselines

  • Naive vector RAG (FAISS cosine)
  • BM25 lexical retrieval (unicode-aware)
  • Hierarchical coarse-to-fine
  • Full MIRA, all components

Controlled runs keep the model, embeddings, dataset and hardware fixed. The measured MuSiQue answer-stage comparison (n=50, identical compression + LLM stage for every system) ships in paper/results_real.md.

What counts as a win

A candidate win requires higher recall or MRR on multi-hop QA at an equal or lower context budget, backed by a paired test. Measured so far: MRR 0.70 vs 0.43 flat (p≈0.0001) on MuSiQue, replicated on HotpotQA — while recall is a statistical tie, and BM25 stays ahead on IndicQA. Wins and ties are both reported.

The memory model

Nodes carry ring · sector · radial_distance · importance · confidence · provenance. Typed edges (has_part, evidence, supports…) form the graph. Sectors are discovered from embedding clusters, never hard-coded categories.

Placement strategies, switchable

Embedding clusters · graph centrality · hierarchy · temporal · hybrid MIRA. The same memory can be laid out five ways and compared; placement itself is an experimental variable.

Local-first inference

Hardware is detected at startup; the runtime selects the largest GGUF that fits with safety headroom (never 100% of RAM/VRAM). On a 4 GB laptop GPU, MIRA runs a 1.5B Q4 model with all layers offloaded. Inference is offline by default; live web search is an explicit opt-in.

Everything is auditable

Grounded answers ship with the retained evidence memories, per-component scores, the multi-hop path taken, and document/page provenance. Identity and parametric answers are labeled and carry no fabricated path or sources. No hidden chain-of-thought: just evidence you can inspect.

Evaluated on real multi-hop data

MuSiQue (Trivedi et al., 2021): answerable 2-hop questions over a shared distractor corpus. MIRA is measured against flat-vector, BM25 and hierarchical baselines; per-question paired bootstrap and Wilcoxon tests back every headline comparison.

Memory that is allowed to forget

A second, optional layer asks whether biologically inspired adaptive dynamics reduce catastrophic forgetting when knowledge keeps arriving — and then answers it by measurement. It remains a hypothesis you can switch off: BIOMIRA_ENABLED = false restores plain MIRA exactly, so the two are compared on identical data.

Forgetting is the baseline problem

Ingest six sequential corpora — A, then B, then C … through F — and re-test every task learned so far after each arrival. A memory system that never forgets is not necessarily one that remembers well; it is one that stores more.

What the tuned stack actually runs

Adaptive decay · a bounded replay buffer · consolidation states · a stability term in the retrieval score · merge reporting. Those five are the tuned, measured configuration (variant J), and each one earned its row in the ablation.

Two further mechanisms — homeostatic normalization and activation-driven ring migration — were implemented and measured, but are disabled in the tuned stack: turning them on (variant K) cost retention 0.938 → 0.914. A mechanism that does not help is reported, not credited.

Computational abstractions only. No claim of biological equivalence.

Nothing is deleted

Decay lowers retrievability; it never removes a node. Conflicts are stored as versions with valid_from / valid_until, so a superseded fact stays answerable to historical questions, and merges keep links to their sources.

Measured: forgetting is halved

0.107 → 0.053

Average MRR forgotten after six sequential corpora land 30 simulated days apart (task A is 150 days stale when task F arrives). Plain MIRA forgets 0.107 of its best score; the tuned adaptive stack forgets 0.053, lifting mean retention 0.873 → 0.938 — with no statistically detectable retrieval cost (p=0.374). The win is roughly halved forgetting, not a doubling of retention.

Ablated before believed

Eleven configurations — vector RAG, MIRA, each mechanism alone, the tuned adaptive stack, and the full stack re-enabled — run the same sequential protocol. A component is credited only where its own row moves the number. BioMIRA < MIRA is a publishable outcome.

Decay alone and consolidation alone are exactly inert; replay alone is noise (p=0.747). The win is the interaction, not a sum — which is why the ladder exists.

Scope, stated plainly: with the LLM frozen this measures memory interference in retrieval, not parametric forgetting in weights. Nothing is ever deleted — the store grows monotonically, 4,487 → 23,516 nodes across the six arrivals. Results are written to data_lab/forgetting_results.json and rendered in the console.

Built to be refuted

Radial distance is formal, not visual

radial = α·semantic + β·hierarchy
+ γ·graph + δ·temporal

Rings are computed, sectors are clustered, and the weights are experimental defaults, the starting point of a sweep rather than a claim.

Ablations isolate the contribution

Run vector_only against full_mira: if retrieval overlap is ~1.0, the extra components added nothing for that query. Jaccard overlap between sets is reported in the Research Lab for exactly this reason.

Metrics from real computation

Recall@k, MRR, context tokens, latency, token-F1, and an optional local LLM-as-judge are computed from actual runs. Treat runs with incomplete manifests as provisional rather than publishable evidence.

Limitations, stated

Token-F1 is a lexical proxy. The judge is the same small model that answers. Centrality is O(n): laptop-scale. These ceilings are documented, not buried.

Memory, arranged
like a mandala.

MIRA tests a formal hypothesis: can a radial, hierarchical, graph-based memory topology, using rings and sectors instead of flat vectors, improve how machines retrieve and reason? The system is built to prove it wrong as easily as right.

What MIRA is not. MIRA is an experimental architecture inspired by the organizational and visual principles of mandalas/yantras. It does not claim that historical mandalas were neural networks or that ancient traditions contained modern AI. Whether radial organization helps is an empirical question: negative results are reported, not hidden.

Does radial topology earn its place?

When model, context budget, dataset and hardware are held constant, does arranging memory in concentric rings around a core, measured by a formal radial distance, retrieve better evidence for multi-hop questions than flat vector search?

The formula under test

score = α·semantic + β·structural
      + γ·radial   + δ·graph
      + ε·importance + ζ·confidence
      + η·recency  + θ·path + ι·activation

Every coefficient is configurable and every component can be switched off, which makes the contribution testable rather than decorative.

The honest baselines

  • Naive vector RAG (FAISS cosine)
  • Vector + graph hybrid
  • Hierarchical coarse-to-fine
  • Full MIRA, all components

Controlled runs keep the model, embeddings, dataset and hardware fixed. Publishable answer-quality claims additionally require the shared answer-stage protocol.

What counts as a win

A candidate win requires higher recall or MRR on multi-hop QA at an equal or lower context budget. The current smoke harness reports retrieval metrics; answer-stage runs are required before making answer-quality claims.

The memory model

Nodes carry ring · sector · radial_distance · importance · confidence · provenance. Typed edges (has_part, evidence, supports…) form the graph. Sectors are discovered from embedding clusters, never hard-coded categories.

Placement strategies, switchable

Embedding clusters · graph centrality · hierarchy · temporal · hybrid MIRA. The same memory can be laid out five ways and compared; placement itself is an experimental variable.

Local-first inference

Hardware is detected at startup; the runtime selects the largest GGUF that fits with safety headroom (never 100% of RAM/VRAM). On a 4 GB laptop GPU, MIRA runs a 1.5B Q4 model with all layers offloaded. Inference is offline by default; live web search is an explicit opt-in.

Everything is auditable

Grounded answers ship with the retained evidence memories, per-component scores, the multi-hop path taken, and document/page provenance. Identity and parametric answers are labeled and carry no fabricated path or sources. No hidden chain-of-thought: just evidence you can inspect.

Built to be refuted

Radial distance is formal, not visual

radial = α·semantic + β·hierarchy
       + γ·graph    + δ·temporal

Rings are computed, sectors are clustered, and the weights are experimental defaults, the starting point of a sweep rather than a claim.

Ablations isolate the contribution

Run vector_only against full_mira: if retrieval overlap is ~1.0, the extra components added nothing for that query. Jaccard overlap between sets is reported in the Research Lab for exactly this reason.

Metrics from real computation

Recall@k, MRR, context tokens, latency, token-F1, and an optional local LLM-as-judge are computed from actual runs. Treat runs with incomplete manifests as provisional rather than publishable evidence.

Limitations, stated

Token-F1 is a lexical proxy. The judge is the same small model that answers. Centrality is O(n): laptop-scale. These ceilings are documented, not buried.
